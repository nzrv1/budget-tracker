## Ограничения этого отчёта — читать перед остальным

Если не прочитать этот блок, часть выводов ниже может показаться категоричнее, чем есть на самом деле:

- **Веб-сайт ещё не задеплоен на момент написания отчёта.** Деплой на Netlify был в процессе (последний известный шаг — `npx netlify-cli login` выполнен успешно, `deploy --prod` ещё не запущен/не завершён). Всё, что ниже помечено **[КОД]** — подтверждено чтением исходников и/или реальными прогонами `tsc`/`vite build`/Playwright на компьютере пользователя в этой и предыдущих сессиях. Всё, что помечено **[ЖИВОЙ ТЕСТ — ожидает URL]** — требует, чтобы я открыл реальную ссылку в браузере; как только она появится, я пройду сайт как обычный пользователь и обновлю эти разделы.
- **Telegram Mini App живьём не тестировался и тестироваться не будет в рамках этого отчёта** — по твоему решению (нет доступа к Telegram-клиенту, скриншоты/запись экрана не предоставлялись). Всё по Mini App ниже — оценка по коду (`lib/telegram.ts`, `App.tsx`, Edge Function), а не по реальному поведению внутри Telegram.
- **У продукта уже была очень глубокая функциональная QA** в предыдущих сессиях — расчётная логика (доходы, бюджеты, категории, часовые пояса, авто-перенос на сбережения) прогонялась через несколько раундов независимого ретеста на реальном окружении пользователя. Поэтому в разделе «Full Bug Report» почти нет открытых **логических** багов — они уже закрыты. Основная новая ценность этого отчёта — слой, который раньше не проверялся вообще: **позиционирование, онбординг, доверие, монетизация, аналитика, Telegram-нативность** — то есть то, что решает, купит ли продукт случайный человек, а не работает ли формула бюджета правильно.
- Ключевое несоответствие, которое стоит обозначить сразу: в описании проекта продукт заявлен как *«умный финансовый калькулятор, который… уведомляет, когда хорошо покупать авиабилеты и одежду, когда копить на отпуск»*. По коду — реализованы бюджеты/цели/важные даты/уведомления по достижению порогов, **но нет никакой интеграции с реальными ценами** (авиабилеты, распродажи одежды) — то есть заявленной «умной» части («сейчас выгодно купить») в продукте физически нет, это общий трекер бюджета с напоминаниями по датам и целям. Это не баг, а разрыв между тем, что обещано в описании продукта, и тем, что построено — критично прояснить до любого публичного запуска с такой формулировкой.

## 1. Executive Summary

**Что это:** персональный трекер бюджета (веб, React/TS/Vite) + Telegram Mini App-надстройка с синхронизацией через Supabase. Данные хранятся локально (`localStorage`), в Telegram — синхронизируются между устройствами через Edge Function с проверкой подписи Telegram `initData`.

**Сильные стороны (подтверждено кодом и реальными тестами):**
- Расчётная логика бюджета/доходов/целей/дат — необычно тщательно вычищена: минимум 20 найденных и исправленных логических багов за историю проекта, каждый закрыт структурным фиксом (общий хелпер), а не заплаткой, и подтверждён реальными `tsc`/`build`/Playwright-прогонами на компьютере пользователя, а не только рассуждением.
- Архитектура синхронизации Telegram (RLS без единой policy + Edge Function как единственная точка входа, проверяющая подпись Telegram) — решение на уровень выше типичного MVP; настоящий secret (токен бота) ни разу не осел в коде или документах.
- Мобильная адаптация и PWA-база (манифест, иконки, safe-area) сделаны осознанно, не для галочки.

**Главные риски для запуска на рынок:**
0. **[Подтверждено живым тестом]** Реальный горизонтальный скролл на мобильной ширине на 4 из 9 экранов (Dashboard, Goals, Important Dates, Budgets) — единственный пункт в этом списке, который является настоящим багом, а не пробелом в продукте, и при этом у него уже есть готовый однострочный фикс (см. Full Bug Report, QA-06/QA-08).
1. Заявленная в описании «умная» функция (уведомления о выгодной покупке авиабилетов/одежды) — не реализована. Продукт по факту — универсальный бюджет-трекер.
2. Нет ни одного экрана, объясняющего новому пользователю, что это за продукт и зачем он нужен — приложение открывается сразу в Dashboard без онбординга, без ценностного предложения, без демо-данных с пояснениями.
3. Нет резервного копирования/экспорта данных для обычного (не-Telegram) веб-пользователя — при очистке кэша браузера или смене устройства данные теряются безвозвратно. Для финансового продукта, который планируется продавать, это критический риск доверия.
4. Нет ни аналитики, ни малейшего механизма измерения поведения пользователей — невозможно понять, где отваливаются люди, до самого запуска.
5. Нет юридических страниц (privacy policy, terms) — обязательны для продукта, работающего с финансовыми данными и Telegram ID пользователя, если он выходит за пределы личного использования.
6. Несостыковка нейминга: бот называется `FinLedger_osis_bot`, приложение внутри — «Ledger» — на публичном старте это читается как недоделанность/тестовая сборка.
7. Единственный вариант «сброса данных» в Settings — по документации audit, это прямое действие без явного подтверждения через двойной шаг/экспорт-перед-сбросом (нужно перепроверить вживую — помечено как риск, не подтверждённый факт).

**Итог одним предложением:** ядро (расчёты, синхронизация) сделано на уровень выше среднего MVP, но всё, что превращает «рабочий инструмент для себя» в «продукт, который можно продавать незнакомым людям» — онбординг, доверие, юридика, аналитика, соответствие заявленной ценности — ещё не начиналось.

## 2. Final Verdict

**Ready for soft launch only** — но именно как soft launch для узкого круга (себя, друзей, ранних тестеров через личную ссылку в Telegram), **не** как публичный продукт с рекламой/продажами. Технически приложение стабильно и не роняется, но отсутствуют базовые для публичного финансового продукта элементы доверия и измерения (см. пункты 2–5 выше). Живой тест сайта может скорректировать эту оценку в любую сторону — обновлю после него.

## 6. UX and Conversion Review

**Сайт:** не пройден живьём — жду URL. По коду: нет landing-страницы, нет CTA, нет объяснения ценности до входа в сам инструмент.

**Telegram Mini App (оценка по коду, не живая):** архитектурно сделано аккуратно — BackButton корректно закрывает модалки вместо сворачивания всего приложения, тема Telegram применяется только при первом запуске без данных (не перезаписывает пользовательский выбор), синхронизация полностью прозрачна (no-op вне Telegram). Не реализовано: `MainButton` (осознанно, разумно для этого масштаба продукта), полный ребрендинг под `themeParams` (тоже осознанно — 6 существующих тем выглядят лучше сырых цветов хоста). **Главный неизвестный** — как это ощущается вживую при первом открытии через кнопку меню: увидит ли пользователь чёткий момент «я в Telegram, а не в браузере» или продукт будет выглядеть как обычный веб-сайт, случайно открытый внутри Telegram.

**End-to-end путь пользователя:**
1. Узнаёт о продукте — канал неизвестен (ссылка на бота от знакомого? Реклама? Не определено).
2. Понимает, что это — **слабое место**: нет ни одного объясняющего экрана.
3. Решает, доверять ли — **слабое место**: нет юридических страниц, нет объяснения, где хранятся данные.
4. Начинает пользоваться — интерфейс сам по себе понятен опытному пользователю трекеров бюджета (знакомые паттерны: транзакции, бюджеты, цели), но не новичку без контекста.
5. Завершает основное действие (добавляет транзакцию/бюджет) — работает корректно, формы валидируются.
6. Получает подтверждение — да, есть success-состояния (подтверждено по коду в модалках).
7. Знает, что делать дальше — снова слабое место, нет прогресса/чеклиста «настроил зарплату → добавь первый бюджет → создай первую цель».
8. Возвращается позже — данные сохраняются локально (или синхронизируются в Telegram), но без экспорта это хрупко.

**Доверие и репутация:** несостыковка имени бота/приложения, отсутствие юридических страниц, отсутствие индикации «ваши данные хранятся локально/в вашем Supabase» — для финансового продукта это первое, на что смотрит осторожный пользователь.

## 9. Suggested Product Improvements

- **Продуктовая логика:** решить судьбу заявленной «умной» функции (авиабилеты/одежда) — либо urls/API интеграция с отслеживанием цен (даже простая: пользователь вручную вписывает целевую цену авиабилета, приложение напоминает при достижении даты/суммы), либо честно сузить позиционирование до «трекер бюджета и целей».
- **UX:** онбординг из 2-3 шагов; явные подсказки для необратимых действий (сброс данных); индикатор «данные хранятся у вас локально / синхронизированы через Telegram» для снятия тревожности по приватности.
- **Сайт:** добавить простой landing-блок перед входом в сам инструмент (даже одна секция: что это, для кого, скриншот) — сейчас пользователь падает прямо в рабочий интерфейс.
- **Telegram Mini App:** живой прогон в реальном клиенте — единственное, что осталось непроверенным технически готовое.
- **Конверсия:** определить целевое действие (см. вопросы ниже) прежде чем добавлять любые CTA.
- **Ретеншн:** уведомления уже частично реализованы (напоминания по целям/датам) — можно усилить push-уведомлениями от бота (Telegram это позволяет нативно), а не только in-app баннерами.
- **Доверие:** экспорт данных + privacy policy — два самых дешёвых и самых важных пункта из всего списка.
- **Аналитика:** внедрить до запуска, не после — см. раздел 8.
- **Монетизация:** пока не определена — см. вопросы ниже.
